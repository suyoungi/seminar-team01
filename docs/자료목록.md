## 3. 매뉴얼 원문에서 확인한 사실 (쪽수 색인)

제도 카드 ①과 A3 표를 채울 때 바로 인용할 수 있도록 적어 둔다.

### 근거와 적용 범위
- 목적: "방위력개선사업으로 획득되는 소프트웨어의 체계적인 개발 및 관리를 위한 프로세스와 산출물 작성표준 등을 규정" — 본문 3쪽
- 관련 문서 20건 가운데 이 연구와 직접 관련된 것: 「국방전력발전업무훈령」, 「방위사업관리규정」, 「무기체계 소프트웨어 개발 지원에 관한 규정」, 「ISO/IEC/IEEE 12207-2017」, 「군용항공기 비행안전성 인증에 관한 업무규정」, 전자정부법, 정보시스템 감리기준(행정안전부 고시) — 본문 3쪽
- 적용 기관: 방위사업청, 소요군, 연구개발주관기관(국방과학연구소, 업체), 기술지원기관(국방과학연구소 정보화기술실, 국방신속획득기술연구원, 국방기술품질원, 국방기술진흥연구소) — 본문 3쪽
- 감항인증 대상 군용항공기 사업은 기종별 감항인증기준에 따라 RTCA DO-178 등을 참고 문서로 산출물 작성 — 본문 4쪽
- 부록 7 적용 사업: 무기체계 연구개발사업, 핵심기술(시험개발), 부품국산화(핵심부품), (경미한) 성능개량. 적용 언어: C, C++, Java, C#을 원칙으로 하되 자동화 도구가 지원하지 않는 경우 제외 — 부록 7-2
- 시험 대상: 개발 SW·공개 SW·자동 생성 코드는 대상, 기개발 SW와 상용 SW는 제외(수정하면 수정 범위는 시험) — 부록 7-2~7-3

### 시험의 정의와 구성
- 신뢰성시험 = 정적시험(코딩규칙 검증, 취약점 점검, 소스코드 메트릭 점검) + 동적시험(코드 실행률 점검) — 본문 11쪽, 부록 7-4
- 보안성 시험 = 행정안전부 「소프트웨어 개발보안 가이드」를 적용하여 개발하였는지 확인하는 시험, 전장관리정보체계 대상 — 본문 10쪽, 부록 7-4
- 보안성 시험 기준: "국정원 CC 인증된 도구를 사용하여 행정안전부 「소프트웨어 개발보안 가이드」 준수 여부, 전장관리정보체계에 한함" — 부록 7-17
- 시험도구는 "관련표준에서 인증된 제품을 사용" — 부록 7-7
- 시험 단위: CSCI 단위 원칙(동적시험은 CSC·CSU 가능) — 부록 7-4

### 참조 표준
- 코딩규칙(부록 6) 관련 표준: MISRA-C 2012·2023, MISRA-C++ 2008·2023, C++ Core Guidelines, Oracle Java Code Conventions, C# Coding Conventions, .NET Framework Design Guideline. 산업 표준으로 IEC 61508, ISO 26262, DO-178B/C, IEC 62279, IEC 60880, EN 50128 — 부록 6-2
- 취약점 점검: "소프트웨어 취약점 점검(CWE-658/659/660) 및 보안약점 점검 목록". 자동화 도구가 지원하는 항목은 모두 적용하고, 지원하지 않는 항목은 대안과 사유를 제출해 사업관리부서·기술지원기관과 협의 — 부록 7-10
- 보안약점 점검 목록 44개(CWE-ID, 중복 여부 표시). 중복 여부는 "코딩규칙점검 및 취약점점검 항목과 중복되는 규칙" — 부록 7-10~7-11
- 소스코드 메트릭: 종류와 제한값은 "개발언어, 도메인 특성을 고려하여 선정"하고 연구개발주관기관이 제시해 소프트웨어 검토회의 등을 통해 결정. 매뉴얼에는 예시(Cyclomatic Complexity 등)만 있고 고정된 한계값은 없음 — 부록 7-12
- 동적시험 등급: 결함 영향도(S1~S4), 발생빈도(E1~E4), 제어 가능성(C1~C3)으로 문장(S)·분기(B)·MC/DC(M) 실행률 종류를 정하는 등급표. 설정된 종류의 실행률 100% 달성 기준 — 부록 7-13~7-15
- 시험확인서 양식 예시의 기준 표기: "MISRA C:2012(AMD1)", "CWE-658(V4.10)", 메트릭 "종류 및 제한값", "OOO Coverage 100%" — 부록 7 별지 2
- 매뉴얼이 참조하는 CWE 버전은 본문·부록 어디에도 규정이 없고, 별지 2 양식 예시에만 V4.10이 보임

### 시험 수행 주체
- 정적시험과 보안성 시험은 연구개발주관기관이 일차 실시 → 기술지원기관이 사업관리부서장과 협의해 결과 확인. 동적시험은 연구개발주관기관 자체 또는 제3자 검증 → 기술지원기관 검토 — 본문 111쪽
- 기술지원기관은 자동화 도구를 운영·유지하고, 결과 검증을 외부 전문기관에 의뢰할 수 있음 — 본문 111쪽
- 개발시험평가 항목에 신뢰성·보안성 시험 반영, 규격화 때 최종 소스코드와 시험 결과 동시 제출, 양산단계 수정 SW도 같은 기준 — 본문 112쪽

### 결과 인정·생략 규정 (제도 안에서)
- 기개발 SW·상용 SW는 수정 없이 재사용이 확정되면 시험 대상에서 제외 가능. "기개발 소프트웨어는 무기체계 소프트웨어 신뢰성시험을 실시한 소프트웨어, 또는 기규격화 소프트웨어" — 부록 7-3
- 통합시험 단계에서 정적시험 뒤 변경이 없으면 개발시험평가 때 정적시험 생략 가능 — 부록 7-9. 동적시험도 같은 규정 — 부록 7-16
- 시험개발에서 개발한 SW를 체계사업에 적용하면 체계개발 기준으로 재수행 — 부록 7-4
- 다른 제도(행안부 진단, CC, K-RMF 등)의 시험·인증 결과를 신뢰성시험 결과로 인정한다는 조항은 본문·부록 7에서 찾지 못함. 보안성 시험이 행안부 가이드와 CC 인증 도구를 기준으로 삼는 것이 유일한 연결 고리임
